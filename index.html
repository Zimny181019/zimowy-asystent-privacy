Privacy Policy

🤖 Bot: Zimowy Guard
📅 Effective Date: July 8, 2026
🔄 Last Revised: September 13, 2026
This Privacy Policy explains what data Zimowy Guard processes on Discord servers, why it is processed, and how long it is retained. Zimowy Guard combines a member engagement toolkit (verification, riddles/quizzes, color roles, reputation, activity leaderboard) with a server protection toolkit (moderation logging, anti-raid, anti-nuke, and blacklist systems).

📋 Data We Collect

  • 👤 User IDs
  • 🏠 Server (Guild) IDs
  • 💬 Channel IDs where activity or moderation actions take place
  • 🎭 Role IDs (used for permission checks, member verification, self-assigned color roles, and role snapshots used to restore roles after a leave/vacation period)
  • 🧩 Riddle/quiz identifiers and the answer option a user selects (A/B/C/D)
  • 📨 Message IDs of riddle/quiz posts (used to update the vote count shown in the embed)
  • 🖱️ Interaction data (which button or select menu a user clicked, and when)
  • ⭐ Reputation point totals, given between users via a text command in a designated channel
  • 📈 A daily message count per user, used only to generate a "most active members" leaderboard
  • 🛡️ Moderation statistics per staff member (message count, kicks, bans, warns, mutes, deleted-message count, tracked voice time, ticket count, staff rating, and how long someone has held a staff role)
  • 📜 A history log of moderation actions (action type, reason, timestamp, and which staff member performed it)
  • 🚨 Security-related event data used for anti-raid and anti-nuke protection: timestamps of member joins during a suspected raid, timestamps and types of suspicious admin-level actions (e.g. mass channel/role changes), and temporary records of original server/nickname values changed during an incident (so they can be restored)
  • 🧳 Vacation/leave-mode data: which roles a user had before going on leave and when their leave period ends, so roles can be automatically restored
  • ⛔ Blacklist records for servers or users found to violate the rules (server/user ID, reason, note, and which staff member added the entry)
The bot does not use the Presence Intent (online/offline status of other users). The bot does use the Message Content Intent, but only to recognize specific text patterns in real time and to run automated spam/security checks (see below) — the text of ordinary messages is never stored, logged, or reviewed by anyone. Interactions (buttons, select menus, slash commands) are processed directly through Discord's interaction system, not by scanning message content.

💬 Use of Message Content

Message text is read in real time, in memory only, for the following purposes:

  • ➕ Recognizing the +rep @user and ?rep @user text commands, used to give and check reputation points in a single designated channel
  • 🔗 Detecting links posted in specific configured channels, so the bot can keep a pinned informational embed visible at the bottom of the channel
  • 🛠️ Recognizing a small set of plain-text maintenance commands, restricted to a few trusted, hardcoded staff user IDs
  • 🚫 Automated anti-spam detection, which briefly checks the rate and similarity of recent messages from an account to identify spam/flood behavior
No message content is saved to our database. Only the outcome of this processing — a point total, a numeric daily message count, a security flag, or an action taken — is stored, always keyed by Discord user ID.

🗄️ Data Storage & Retention

All data is stored locally in a SQLite database on the bot's own hosting server. Nothing is sent to or stored by any third party.

🤝 Data Sharing

  • ✗ Data is never sold or shared with third parties
  • ✗ Data is never used for advertising purposes outside the server
  • ✓ Aggregated vote counts, reputation totals, and the activity leaderboard are visible to server members, as they are shown publicly in embeds (raw message content is never disclosed or displayed)
  • ✓ Moderation logs, staff statistics, and blacklist entries are visible only to server staff with the appropriate permissions

🔒 Data Security

Bot credentials, including the Discord bot token, are stored securely using environment variables and are never hardcoded, exposed publicly, or shared.

👶 Children

The bot is intended to be used in accordance with Discord's Terms of Service, which require users to be at least 13 years old (or the minimum age required in their country). We do not knowingly collect data from users below this age.

✋ Your Rights

You may request deletion of your data (reputation points, activity counts, recorded votes, role/verification data, vacation records, or moderation-related data tied to your account) at any time by opening a ticket in the #ticket channel on our Discord server. Requests are reviewed by staff and your data is deleted upon verification of your Discord user ID, except where retaining a moderation record is reasonably necessary for server safety and accountability. You may also stop using the bot's features at any time.

✏️ Changes to This Policy

We may update this Privacy Policy from time to time. Significant changes will be announced on the server. Continued use of the bot after changes take effect constitutes acceptance of those changes.

✉️ Contact

For any questions regarding privacy or data handling, please contact server staff through the ticket system.
