Privacy Policy

🤖 Bot: Zimowy Guard
🧩 Modules covered: Community & Security Features, Partnership System & Ticket System
📅 Effective Date: July 8, 2026
🔄 Last Revised: September 13, 2026
Zimowy Guard now operates as a single bot combining its original community and server-protection features with the previously separate partnership system and ticket system. This Privacy Policy explains what data the bot processes on Discord servers across all modules, why it is processed, and how long it is retained.

📋 Data We Collect

Community & Security Module

  • 👤 User IDs (members, staff performing moderation or admin actions)
  • 🏠 Server (Guild) IDs
  • 💬 Channel IDs (reputation channel, guessing-game channel, moderation log channel, sticky-message channels)
  • 🎭 Role IDs (verification role, color roles, admin roles, leave/"urlop" role, guessing-game reward roles, birthday role)
  • 🧩 Riddle/quiz vote records: which user voted, their choice, and the riddle ID (one vote per user per riddle)
  • ⭐ Reputation point totals awarded between members via the +rep / ?rep commands
  • 🌴 Leave/"urlop" records: the roles held before leave (stored so they can be restored), and the leave start/end timestamps
  • 📜 Moderation action logs: action type (kick, ban, warn, mute, message deletion), reason, the staff member responsible, and the target user, for accountability purposes
  • 🚨 Anti-raid, anti-nuke, and anti-spam event data: join timestamps, flagged/suspicious admin-level actions, and the accounts involved, used solely to detect and respond to abuse
  • ⛔ An internal blacklist maintained by the bot owner/staff (blacklisted user/server IDs and reasons), separate from the mirrored partnership blacklist described below
  • 🎮 Guessing-game data: number of guesses, win counts, leaderboard standings, and configured odds
  • 🎂 Birthday entries (date submitted by the user) and their approval status
  • 📥 Invite-tracking records: which invite code was used and by whom, to attribute new members to the inviter

Partnership Module

  • 👤 User IDs (server owners/representatives, realizators, partners)
  • 🏠 Server (Guild) IDs, including IDs of partner servers referenced in invite links
  • 💬 Channel IDs used for the partnership system and the log channel
  • 🎭 Role IDs (realizator role, partner role, leave/"urlop" role, permission checks)
  • 🔗 Discord invite links submitted in the designated partnership channel
  • 🤝 Partnership records: which realizator handled which partnership, the partner's user ID, the associated invite link, the date, and the reward rate assigned to that partnership
  • ⏱️ Norm/quota tracking data for realizators: cycle start time, whether a reminder was already sent, and the count of partnerships completed within the current cycle
  • 🚫 A local mirror of a blacklist (blocked server IDs, server names, and block reasons), synced from a separate, independently operated blacklist bot
  • 🎁 Completed-partnership counters used to determine when a realizator has reached the threshold for a reward payout

Ticket Module

  • 👤 User IDs
  • 💬 Channel IDs and channel topics (used to link a ticket channel to the user who opened it)
  • 🎭 Role IDs (used for permission checks, ticket access management, the "urlop"/leave role, and the verification role)
  • 📝 Full content of messages sent inside ticket channels (see section below)
  • 🕐 Timestamps of ticket creation and closure
The "urlop"/leave role is shared logic across all modules: while a member holds it, their access to open tickets is restricted and their realizator norm is paused.
The bot does not use the Presence Intent (online/offline status of other users) — this is not required by, and is not used by, any bot feature across any module. The bot also does not process voice activity.

Message Content — What Exactly Is Processed

The bot requires the Message Content Intent and the Server Members Intent. How message content is handled differs by feature:

  • 🎮 Guessing-game channel: the bot reads submitted messages only to check whether they contain a valid numeric guess and compare it against the target number — the message text itself is not permanently stored, only the resulting win/guess count.
  • 🔗 Partnership channel: the bot only extracts the presence/value of a Discord invite link (discord.gg / discord.com/invite) and any mentioned user — it does not permanently store the full text of these messages.
  • 🎫 Ticket channels: the bot temporarily stores the full text of every message sent inside a ticket channel — author username, User ID, and timestamp for each — compiled into a transcript when the ticket is closed or the owner leaves the server.
The bot does not read or store message content from any other channel on the server outside of these specific contexts.

🗄️ Data Storage & Retention

Data is stored locally on the bot's hosting server (SQLite databases) and used exclusively to support the features described in this Policy.

  • 🧩 Riddle/quiz vote records are retained to display final results and are not reused once a riddle is closed.
  • ⭐ Reputation totals are retained indefinitely and may be reset or corrected by staff.
  • 🌴 Leave/"urlop" role snapshots are deleted once roles are restored at the end of the leave period.
  • 📜 Moderation logs are retained for accountability purposes until removed by staff.
  • ⛔ Internal blacklist entries are retained until removed by the bot owner or staff.
  • 🎮 Guessing-game win counts and leaderboard entries are retained until reset or corrected by administrators.
  • 🎂 Birthday entries are retained until removed by the user or staff.
  • 📥 Invite-tracking records are retained for moderation and community-management purposes and may be cleared by staff.
  • 🤝 Partnership records are automatically removed once a partnership ends (e.g. when a partner leaves the server).
  • 🚫 The mirrored partnership blacklist is fully replaced every time the source blacklist bot broadcasts an update, so it never accumulates stale entries.
  • 🎫 Message content collected inside a ticket channel is only compiled into a transcript at the moment the ticket is closed (manually or automatically). The transcript is temporarily written to a log file on the bot's hosting server, sent as an embed with an attached log file, and then immediately deleted from the bot's disk.
The bot does not maintain a persistent database of ticket message content or raw guessing-game message text. Once a ticket transcript has been generated and delivered, the only copies that remain are the ones described in "Data Sharing" below.

🤝 Data Sharing

  • ✗ Data is never sold or shared with third parties
  • ✗ Data is never used for advertising purposes outside the server
  • ✗ The bot does not automatically communicate or exchange data with the ZR Points bot — reward points are credited manually by server staff, based on the completed-partnership count shown by this bot, after the realizator opens a payout ticket
  • ✓ Blocked-server data used for partnership restrictions is received from a separate, independently operated blacklist bot
  • ✓ Ticket transcripts are sent to a dedicated staff log channel on the server, visible to server administrators/staff
  • ✓ Ticket transcripts are sent via direct message to the ticket owner and, where applicable, to the staff member who closed the ticket
  • ✓ Data may be visible to server administrators as part of standard moderation features (e.g. the moderation log channel, the partnership log channel)

👶 Children

The bot is intended to be used in accordance with Discord's Terms of Service, which require users to be at least 13 years old (or the minimum age required in their country). We do not knowingly collect data from users below this age.

✋ Your Rights

You may request deletion of your data — including reputation totals, leave/"urlop" history, moderation log entries (where legally permissible), guessing-game or leaderboard entries, birthday information, invite-tracking records, partnership records, norm/cycle history, or previously delivered ticket transcripts (e.g. removal of a message from the staff log channel) — at any time by contacting server staff through the ticket system. You may also stop using the bot at any time — no new data will be actively collected about you going forward.

✏️ Changes to This Policy

We may update this Privacy Policy from time to time. Significant changes will be announced on the server. Continued use of the bot after changes take effect constitutes acceptance of those changes.

✉️ Contact

For any questions regarding privacy or data handling, please contact server staff through the ticket system.
